# Безопасность

TailScaleKeen управляет сетевым клиентом и нативной интеграцией с правами root. Устанавливайте только из доверенного источника. Это локальный административный инструмент; не публикуйте его HTTP порт в интернет.

- Собственные аккаунты, случайные сеансы, HttpOnly/SameSite=Strict, CSRF token и проверка Origin.
- Пароли: соль и PBKDF2-HMAC-SHA256, 600 000 итераций. Минимум 6 символов сохранён для совместимости; рекомендуются длинные уникальные пароли. Повтор пароля обязателен.
- Ограничены число запросов входа, параллельные HTTP подключения, размер тела, истории и загрузок.
- Shell не вызывается с текстом HTTP-запросов. Параметры CLI передаются отдельными аргументами и проверяются.
- Ключ регистрации передаётся через временный закрытый файл, а не в аргументе процесса.
- Панель и Tailscale обновляются из фиксированных HTTPS источников. SHA256 защищает от повреждения; файл суммы из того же GitHub Release **не является независимой цифровой подписью**. Доверие к аккаунту и инфраструктуре GitHub остаётся необходимым.
- Архив панели проверяется до распаковки: типы файлов, размеры, имена, отсутствие ссылок/traversal, манифест и версия. Обновление не запускается автоматически по расписанию.
- Первый вход без setup-кода предназначен для доверенной LAN. Настройте аккаунт сразу; не открывайте неинициализированную панель недоверенным устройствам.
- Ни телеметрии проекта, ни предварительно заданных серверов/клиентских ключей в дистрибутиве нет. Контроллер Tailscale/Headscale получает обычные данные официального клиента.

При сообщении об ошибке удалите токены, пароли, приватные ключи, реальные адреса, полные prefs и содержимое `tailscaled.state`. Пользовательские журналы/backup/config не должны попадать в репозиторий. Для сообщения об уязвимости используйте [Security проекта](https://github.com/Zhanchuraev/TailScaleKeen/security), если private reporting доступен; не прикладывайте секреты в публичный Issue.

Поддерживается последний опубликованный стабильный релиз проекта.

Публичное получение анонимной сессии имеет отдельный лимит и не вытесняет авторизованных администраторов. Ожидающие подтверждения изменения ограничены по числу и времени жизни; ключ регистрации удаляется из отменённого или истёкшего предпросмотра. Непосредственно перед сетевой записью под межпроцессной блокировкой повторно проверяется версия настроек.

API и диагностические отчёты не кешируются браузером. Только общедоступные статические ресурсы могут использовать условный запрос ETag/304 с обязательной перепроверкой. Обезличенный отчёт строится из явного списка полей и требует входа; сырые конфигурации, адреса и тексты исключений в него не копируются.
