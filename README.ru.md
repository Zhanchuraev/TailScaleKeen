# TailScaleKeen: установка, возможности и настройка

## Требования

- Keenetic/Netcraze ARM64 (`uname -m` → `aarch64`) с уже установленным **Entware aarch64-k3.10** и смонтированным `/opt`.
- Компоненты прошивки для Entware и TUN/OpkgTun, доступ в SSH **Entware** от root. Нативная командная строка роутера и Entware shell — разные среды.
- Python 3.11+, curl, сертификаты CA. Установщик установит зависимости из вашего текущего репозитория Entware, если они отсутствуют.
- Свободное место: рекомендуется не менее 300 МБ для первой установки и обновления клиента; обновление одной панели требует 64 МБ.
- Доступ по HTTPS к GitHub, `raw.githubusercontent.com` и `pkgs.tailscale.com`, правильные дата и время.

Установщик **не форматирует носитель, не устанавливает Entware и не обновляет KeeneticOS/NetcrazeOS**. Если Entware отсутствует, сначала установите его по инструкции для вашей модели. Совместимый архив: [aarch64-k3.10 installer](https://mirrors.bfsu.edu.cn/entware/aarch64-k3.10/installer/aarch64-installer.tar.gz); это дистрибутив Entware, а не архив TailScaleKeen. Установка этого архива и выбор носителя выполняются средствами роутера.

## Одна команда установки

```sh
(set -e; opkg update; opkg install curl ca-bundle; mkdir -p /opt/tmp; f="$(mktemp /opt/tmp/tailscalekeen.XXXXXX)"; trap 'rm -f "$f"' EXIT; curl -fLsS --connect-timeout 15 --max-time 90 https://raw.githubusercontent.com/Zhanchuraev/TailScaleKeen/main/install.sh -o "$f"; sh "$f")
```

Скрипт загружает последний стабильный релиз проекта, проверяет SHA256 и манифест файлов, устанавливает панель и последний стабильный официальный Tailscale ARM64. Ключи существующего поддерживаемого клиента сохраняются. Скрипт не выполняет массовый `opkg upgrade` и не заменяет зеркало Entware.

После установки: `http://<локальный-IP-роутера>:8092/`. Если порт занят, скачайте установщик и запустите `sh install.sh --port 8093`. При повторной установке сохраняется ранее выбранный порт.

Для обновления только панели из локального распакованного релиза без обновления клиента:

```sh
sh install.sh --source "$PWD" --panel-only
```

Предпочтительный способ последующих обновлений — кнопка в панели: у неё есть проверка запуска и автоматический откат к прежнему коду.

## Первый вход и доступ

Форма первого входа просит логин, пароль и повтор пароля. Код первоначальной настройки не требуется. Пароль — от 6 до 256 символов; цифры допустимы, длинный уникальный пароль предпочтительнее. Учётная запись независима от XKeen WebUI и нативных пользователей роутера. Настройте её сразу после установки в доверенной локальной сети.

В **Клиент и панель** можно поменять логин и пароль с подтверждением текущего пароля. Другие сеансы будут завершены.

Сброс всей учётной записи через SSH:

```sh
tailscalekeen reset-password
```

Команда удаляет **логин и хеш пароля**, отзывает сеансы и возвращает форму первого входа. Сеть, ключ устройства, порт и заметки сохраняются. Старая команда `tailscale-panel` остаётся совместимым псевдонимом.

Смена порта: задайте свободный порт 1024–65535, откройте предложенный новый адрес и подтвердите его за 120 секунд. Старый адрес работает до подтверждения; без него смена отменяется. При работе через обратный прокси предусмотрите его отдельную перенастройку.

Панель по умолчанию слушает `0.0.0.0:8092`; доступ ограничивает firewall самого роутера. Не создавайте публичное перенаправление этого порта. HTTP используйте в доверенной LAN или через защищённую VPN; для других сетей нужен настроенный вами HTTPS reverse proxy. Проект не открывает порт из интернета и не выдаёт сертификаты автоматически.

## Подключение Tailscale или Headscale

1. Откройте **Клиент и панель → Подключение к сети**.
2. Для официального сервиса оставьте `https://controlplane.tailscale.com`. Для Headscale укажите HTTPS URL **вашего** контроллера, например `https://headscale.example.com`.
3. Задайте имя устройства. Можно оставить поле ключа пустым и открыть ссылку браузерного входа; для Headscale следуйте его процедуре регистрации узла.
4. Альтернатива — ключ регистрации вашей сети. Он передаётся Tailscale через файл с ограниченными правами и удаляется после команды. Не вставляйте реальные ключи в GitHub Issues.
5. Просмотрите изменения и примените. Проверьте состояние **Подключён** и отсутствие предупреждений.

Одновременно поддерживается **одна** сеть. Смена сервера может прервать прежний доступ и потребовать новой регистрации. Панель не создаёт сервер Headscale, аккаунт Tailscale, ACL/grants и не одобряет маршруты на контроллере.

## Подключение Keenetic / OpkgTun

Раздел **Подключение Keenetic** показывает найденное подключение, MTU, состояние и связанные политики. Для чистой установки можно создать OpkgTun: сначала показываются конкретные изменения. Существующее подключение не перезаписывается.

После создания подключение видно в штатном веб-конфигураторе роутера. Если домашним устройствам нужен выход через Tailscale, создайте/выберите подходящую политику доступа в самой KeeneticOS и назначьте ей нужных клиентов. Добавление OpkgTun само по себе не переводит всю домашнюю сеть в VPN.

Поддерживаемое размещение клиента: `/opt/bin/tailscale`, `/opt/bin/tailscaled`, служба `/opt/etc/init.d/S06tailscaled`, TUN вида `opkgtun0`…`opkgtun15`. Для новой установки выбирается свободный OpkgTun; существующий поддерживаемый TUN сохраняется. Иные демоны, контейнеры, несколько экземпляров или другие схемы запуска автоматически не заменяются: сначала приведите их к поддерживаемой схеме с резервной копией.

Для чистой установки панель добавляет собственную интеграцию: маршруты пиров/принятых подсетей перед правилами NDM, обход туннеля для служебной метки Tailscale, доступ из TUN и SNAT локальных клиентов. Общий выход WAN не заменяется. Свою LAN и default/split-default маршруты чужого Exit node эта интеграция не переносит поверх штатных политик. Используются собственные цепочки `TSK_*`, приоритеты `ip rule` 69/70 и hook `96-tailscale-panel.sh`. Конфликт с чужими приоритетами/цепочками останавливает настройку без их замены. Поддерживается до 256 отдельных префиксов на семейство адресов. При найденных прежних поддерживаемых скриптах политика остаётся под их управлением: дублирующая интеграция не включается.

## Exit node: два разных режима

**Использовать другой Exit node.** В **Выход в интернет** выберите доступный узел. «Доступ к своей LAN» сохраняет доступ самого клиента к ближайшей локальной сети при использовании внешнего Exit node. Это не переключатель DHCP или домашней Wi-Fi сети.

**Раздавать интернет через этот роутер.** Включите объявление своего Exit node, затем разрешите его в административной консоли вашей сети. На другом устройстве выберите роутер как Exit node. Домашняя LAN при этом продолжает работать. Tailscale не допускает одновременное объявление своего Exit node и использование чужого; панель показывает связанные изменения до применения.

Для клиентов, выбравших **этот** роутер как Exit node, доступен выбор выхода:

- **Как настроено в роутере** — используется существующая маршрутизация.
- Доступный интернет-провайдер/WAN — обнаруживается из реальной конфигурации.
- Политика Keenetic — в том числе политика другого VPN, если у неё есть рабочая выходная таблица.
- **XKeen** — только при наличии совместимых действующих force-цепочек XKeen; панель не устанавливает прокси и не содержит VLESS-ссылок.

Правила этого выбора ограничены трафиком, **пришедшим из Tailscale**. При недоступности выбранного выхода трафик блокируется, чтобы не уйти через другой WAN. LAN, служебные и приватные назначения исключаются. Для выхода без рабочего IPv6 IPv6 блокируется. Фактическая доступность TCP/UDP зависит от выбранного VPN, сервера и провайдера; это не универсальная поддержка любого стороннего прокси.

## Подсети и DNS

В **Подсети и DNS** перечислите локальные префиксы по одному в строке, например `192.168.10.0/24`. После применения одобрите их на сервере Tailscale/Headscale. Дублирующиеся подсети разных площадок требуют отдельного проекта маршрутизации.

- **Принимать маршруты** — использовать подсети, объявленные другими устройствами.
- **SNAT** — подменять адрес источника при доступе через subnet router; обычно упрощает обратный маршрут.
- **Фильтрация соединений** — отслеживание перенаправляемых соединений средствами Tailscale. При сложной схеме нескольких VPN проверяйте путь в обе стороны.
- **Принимать DNS** — применять DNS настройки tailnet к клиенту. На роутерах настройку обычно оставляют выключенной, сохраняя штатный DNS. Панель не переписывает DHCP и DNS WAN.
- **Блокировать входящие** — запрет входящих соединений от других узлов к этому устройству.

## Клиенты и диагностика

Раздел **Клиенты** показывает онлайн-статус, адреса, direct/DERP, переданный и принятый трафик. Рядом с отображаемым IP расположена кнопка копирования: она работает и через обычный HTTP. При запрете буфера обмена браузером можно выделить адрес и скопировать его вручную. MAC-адреса удалённых узлов в Tailscale status не передаются и в таблице не подменяются MAC-адресами клиентов LAN. КБ/МБ/ГБ рассчитываются по основанию 1000. Счётчики Tailscale могут сброситься после перезапуска; это не биллинг и не постоянная статистика за месяц.

В карточке устройства можно оставить заметку и изменить URL его веб-интерфейса. Карточки хранятся только на этом роутере отдельно для каждого сервера управления. Кнопка своего роутера открывает TailScaleKeen; для других узлов по умолчанию предлагается `http://<Tailscale-IP>:5252/`.

Встроенная панель порта 5252 должна быть включена на целевом устройстве и разрешена ACL. Современный клиент может не принимать вход на 5252 напрямую из LAN: открывайте его с устройства, подключённого к Tailscale. Возможность управления через встроенную панель зависит от контроллера; некоторые версии Headscale не реализуют подтверждение личности. Это отдельный интерфейс, не TailScaleKeen.

В **Диагностика** доступны штатные ping/netcheck/проверки маршрутов и состояния. В проверке устройства можно выбрать **Соединение: direct / DERP** или **Туннель WireGuard: TSMP**. TSMP проверяет передачу пакетов внутри туннеля; доступ к конкретному приложению дополнительно зависит от его службы, ACL и межсетевого экрана.

Кнопка **Проверить состояние** показывает подключение Tailscale, согласованность трёх версий клиента (CLI, файл демона, работающий демон), наличие TUN, отдельную учётную запись панели, права файлов и место для обновлений. Это локальная проверка компонентов, а не сканирование всей сети или всех правил ACL. Сетевые настройки не меняются. Память и количество потоков относятся к процессу панели, а счётчик свободного места — к её носителю.

**Скачать отчёт** выдаёт JSON по строгому списку полей: версии, результаты проверок, количество устройств/подсетей и показатели ресурсов. В него не включаются IP, DNS-имена, URL контроллера, логин, заметки, журналы, prefs и ключи. Такой отчёт можно приложить к сообщению об ошибке. Полные журналы и копии настроек по-прежнему считайте приватными. **Журналы** и история заданий ограничены по объёму; ключи регистрации маскируются. Сетевые адреса в диагностике относятся к вашему роутеру и видны авторизованному администратору.

## Резервные копии

Копии в интерфейсе сохраняют параметры, которые умеет восстанавливать панель. Их можно скачать, импортировать, удалить и восстановить с предварительным просмотром. Это **не** полная копия Entware, прошивки, приватного ключа Tailscale или контроллера. Для аварийного восстановления делайте отдельную защищённую копию носителя и состояния Tailscale.

## Обновления

**Панель:** **Клиент и панель → Обновить WebUI TailScaleKeen → Применить**. Код загружается только из стабильных Releases `Zhanchuraev/TailScaleKeen`. Проверяются SHA256, безопасный состав архива, манифест каждого файла и версия. Старые или предварительные релизы автоматически не устанавливаются.

Внешний процесс заменяет код, перезапускает только панель и проверяет её HTTP API. При неудаче запуска возвращает предыдущий код и версии настроек. Учётная запись, выбранный порт, заметки, маршруты и демон Tailscale сохраняются. Браузер показывает ход операции; после перезапуска нужно войти снова. Прежний код сохраняется в `/opt/share/.tailscale-panel-previous` как одна копия для отката. Выключение питания посередине файловой операции может потребовать восстановления через SSH — это не двухраздельная прошивка.

Команды SSH:

```sh
tailscalekeen check-update
tailscalekeen update
tailscalekeen status
```

**Клиент:** отдельная кнопка «Обновить клиент Tailscale» использует официальный `pkgs.tailscale.com/stable`, сверяет SHA256, ключ устройства, ID/IP и настройки. Клиент временно перезапускается; при доступе к роутеру исключительно через Tailscale используйте резервный путь управления. Прошивка и остальные приложения не обновляются.

## Полное удаление одной командой

```sh
tailscalekeen uninstall --purge
```

Предварительный список без изменений:

```sh
tailscalekeen uninstall --dry-run
```

Удаляются поддерживаемые файлы панели/клиента, локальные ключи, заметки, учётка, журналы, собственные правила, TUN-подключение и выделенные только Tailscale политики. Удаление означает потерю текущей регистрации на этом роутере. Если в штатной панели есть несохранённые изменения, операция остановится до их разрешения.

Общие Entware/Python/curl, XKeen, ZeroTier и пользовательские архивы за пределами каталогов панели сохраняются. Запись устройства на сервере, его одобренные маршруты и скопированные пользователем резервные копии удаляются отдельно. Неизвестные сторонние интеграции не обещаются к автоматическому удалению.

## Файлы и служба

| Назначение | Путь |
|---|---|
| Код | `/opt/share/tailscale-panel` |
| Настройки, учётка, заметки, задания | `/opt/etc/tailscale-panel` |
| Служба панели | `/opt/etc/init.d/S98tailscale-panel` |
| Служба клиента | `/opt/etc/init.d/S06tailscaled` |
| Основная команда | `/opt/bin/tailscalekeen` |
| Совместимый псевдоним | `/opt/bin/tailscale-panel` |
| Журнал панели | `/opt/var/log/tailscale-panel.log` |

Исторические имена каталогов сохранены для обновления существующих установок без переноса ключей и учётной записи.

## Сборка собственного релиза

На Linux/Python 3.11+ запустите тесты, проверку публичного состава и сборку командами из README. Архив содержит только разрешённые исходники, web-ресурсы, установщик и документацию. Runtime state и локальные отчёты не включаются. Для форка измените фиксированный репозиторий в `panel/releases.py`, `install.sh`, ссылках интерфейса и документации. Поле произвольного URL обновлений намеренно не принимается от браузера.

Перед выпуском измените `VERSION` и константу в `panel/core.py`, опишите изменения в `CHANGELOG.md`, создайте тег `vX.Y.Z`. Workflow релиза проверяет код и публикует `tailscalekeen.tar.gz` и `.sha256`. Опубликованные артефакты должны быть доступны без авторизации.
